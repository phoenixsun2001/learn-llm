## 学习目标

完成本章后，你将能够：

- 理解子智能体（Subagent）的概念，以及它与主 Agent 的分工
- 熟练使用内置的 Explore 子智能体完成代码库调研
- 判断哪些任务适合委派给子智能体，哪些应当主 Agent 亲自处理
- 结合目标模式，构建「探索 → 规划 → 执行」的高效工作流

## 什么是子智能体

子智能体（Subagent）是在主 Agent 之下、专门处理某一类任务的辅助智能体。可以把它理解为主 Agent 的**助手**：当主 Agent 遇到需要大范围搜索、深入调研的任务时，它可以委派一个子智能体去完成，自己则专注在核心的执行工作上。

这种分工的价值在于**上下文隔离与专注**：

- 主 Agent 的上下文保持干净，不会被海量搜索结果撑爆
- 子智能体在独立的上下文里完成调研，只把**结论**带回给主 Agent
- 主 Agent 基于精炼的结论做决策，质量更高、更不容易跑偏

## 内置 Explore 子智能体

ZCode 当前已经支持内置的 **Explore** 子智能体。它是一个**只读的文件搜索和代码库调研专家**，适合处理大范围检索、调用链梳理、代码结构理解这类探索任务。

### Explore 的特点

| 特性 | 说明 |
|------|------|
| **只读** | Explore 只检索、不修改任何文件，安全无副作用 |
| **大范围** | 擅长在庞大的代码库中做广度搜索 |
| **结论导向** | 读取的是代码，返回的是提炼后的结论，而非原始片段堆砌 |

因为 Explore 是只读的，你可以放心地让它去翻阅整个仓库，不必担心它误改代码。

### Explore 适合的任务

Explore 在以下场景中表现出色：

- **定位实现**：「处理用户登录的代码在哪些文件里？」
- **梳理调用链**：「orderService.create 被谁调用？它又调用了哪些下游？」
- **理解结构**：「这个项目的目录是怎么组织的？各模块职责是什么？」
- **收集证据**：「哪些地方用到了即将废弃的旧 API？给我完整列表」
- **代码调研**：「项目里现有的错误处理模式有哪几种？分别用在哪些层？」

这类任务的共同点是：**需要在大量文件里搜索、归纳，但不需要立刻动手改**。先让 Explore 摸清情况，主 Agent 再基于结论精准执行，效率远高于边搜边改。

## 如何委派任务给 Explore

当主 Agent 判断当前任务需要调研时，会自动委派给 Explore 子智能体。你也可以在需求中明确引导：

```text
我想给项目的所有 HTTP 接口统一加上请求日志。
先帮我搞清楚：现在所有接口入口都在哪里、用的什么框架、
现有的中间件机制是怎样的。搞清楚后，再给我一个改造方案。
```

在这个例子里，「搞清楚现状」这部分会被交给 Explore 去做。Explore 会在代码库里检索路由定义、中间件注册、现有日志写法，把归纳后的结论（而不是一堆零散的代码片段）带回来。主 Agent 拿到结论后，据此设计改造方案。

## 主 Agent 与子智能体的分工

理解分工，能帮你更好地组织需求。一个实用的判断标准是**「读」还是「写」**：

| 任务性质 | 谁来做 | 原因 |
|---------|--------|------|
| 调研、检索、理解代码 | Explore 子智能体 | 大范围、只读、需要归纳 |
| 设计、实现、修改代码 | 主 Agent | 需要决策、需要写权限 |
| 验证、测试、跑命令 | 主 Agent | 需要执行与状态变更 |

把探索和执行分开，让各自专注自己擅长的事，这是「子智能体」架构的精髓。

## 结合目标模式的高效工作流

Explore 子智能体和目标模式（`/goal`）搭配，能构建出非常强大的工作流。下面是一个典型范式：**探索 → 规划 → 执行 → 校验**。

### 场景：为一个陌生模块添加功能

假设你要给一个你不熟悉的老模块加新功能：

```text
[探索阶段]
（委派 Explore）
先帮我彻底搞懂 src/legacy/billing/ 这个模块：
1. 它的核心入口和数据流
2. 涉及的关键数据结构
3. 现有的测试覆盖情况

[规划阶段]
（主 Agent 基于 Explore 的结论）
基于以上调研，给我添加「按月自动开票」功能的实现方案，
说明要改动哪些文件、风险点在哪。

[执行阶段]
/goal 按上述方案实现「按月自动开票」功能，
并补充单元测试，确保 npm run test 通过

[校验阶段]
（目标模式自动迭代，直到测试通过）
```

在这个流程里：

- **Explore** 负责把陌生模块摸透，你无需自己一行行读代码
- **主 Agent** 基于调研结论做方案设计和实现
- **目标模式**负责把实现推进到测试通过

每个环节各司其职，整个过程你只需要提供方向和验收。

## 当前能力范围

需要了解 ZCode 子智能体当前的能力边界，避免误用：

- **已支持**：内置 Explore 子智能体，处理只读检索与调研
- **暂不支持**：自定义子智能体（暂不能自己创建具有特定职责的新子智能体）

这意味着，现阶段你应当把子智能体理解为「一个内置的调研专家」，而非可自由扩展的角色集合。当主 Agent 需要摸清代码库现状时，交给 Explore；当需要执行具体改动时，仍由主 Agent 完成。

## 最佳实践

1. **先探索，后执行**：面对不熟悉的代码，先让 Explore 调研，再让主 Agent 动手。盲目动手是大返工的常见原因。
2. **让 Explore 给结论**：委派时明确要求「归纳结论、列出文件清单」，而不是「把所有相关代码贴给我」——后者会浪费上下文。
3. **结合目标模式**：探索完成后，用 `/goal` 把执行交给目标模式自动迭代，最大化减少手动干预。
4. **范围要清晰**：委派 Explore 时给出明确的搜索范围或关键词，比「随便看看」效果好得多。

## 小结

子智能体是主 Agent 的得力助手。当前内置的 Explore 子智能体专注于只读检索与代码库调研，让主 Agent 的上下文保持干净、决策保持精准。掌握「探索 → 执行」的分工，再配合目标模式，你就掌握了 ZCode 处理长程任务的核心方法论。
