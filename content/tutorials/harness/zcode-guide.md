# ZCode 实战指南：面向长任务的 Agentic 开发环境

ZCode 是智谱 Z.ai 推出的全功能 **Agentic Development Environment（ADE）**，专门面向 **Long Horizon Task**（长跨度、多步骤的复杂开发任务）。它让 AI Agent 在同一个上下文里，从规划一路推进到编码、验证、收口，端到端、稳定可控地完成开发工作。

ZCode 3.0 围绕 **GLM-5.2** 完成深度联调与专项优化，聚焦自研 **ZCode Agent** 能力，让模型、工具和执行工作流结合得更紧密。

## 你将学会什么

完成本指南后，你将能够：

- 理解 ZCode 与传统 AI 编码助手的差异（长任务 + 稳定性）
- 完成 ZCode 的安装与模型接入（BigModel / Z.ai / 第三方）
- 用 ZCode Agent 发起任务、补充上下文、引用文件
- 区分不同执行模式，选择适合当前任务的方式
- 用 Plan 模式把复杂任务拆成可控的步骤并推进到验证收口

---

## 一、认识 ZCode

### 它解决什么问题

传统的 AI 编码助手擅长"一问一答"的短任务：改一个函数、补一段逻辑、解释一段代码。但真实开发里，大量任务是**长跨度**的——比如"给这个项目加上完整的用户认证模块"、"重构这个服务的错误处理"、"从零搭一个 RAG 应用"。

这类任务有共同特征：

| 特征 | 带来的挑战 |
|------|-----------|
| 步骤多（十几到几十步） | 上下文容易丢失，AI 忘记最初目标 |
| 需要持续理解项目状态 | 文件、终端输出、Git 状态都要同步进上下文 |
| 中间有验证环节 | 写完要跑测试、看预览，根据结果修正 |
| 需要人为确认关键节点 | 不能一路狂奔，要有可控的检查点 |

ZCode 的核心能力就集中在两件事：**长任务** 和 **稳定性**。自研 ZCode Agent 会在同一个任务里持续理解目标、文件、终端结果、浏览器上下文、执行模式和 Git 状态，让复杂任务可以从规划一路推进到验证收口。

### 和其他工具的定位差异

| 维度 | ZCode | Claude Code / Codex | Cursor / Trae |
|------|-------|---------------------|---------------|
| 形态 | 终端 + Web 工作台（ADE） | CLI 编码助手 | AI IDE |
| 核心模型 | GLM-5.2（深度联调） | Claude / GPT | 多模型可选 |
| 强项 | 长程任务、稳定性 | 命令行全流程 | 项目内交互式编辑 |
| 适合场景 | 跨度大、步骤多的端到端开发 | 终端驱动的日常编码 | IDE 内的实时补全/重构 |

> 💡 不是替代关系。ZCode 适合"开一个长任务让它端到端跑"，CLI 助手适合"在终端里高频交互"，IDE 适合"写代码时的实时辅助"。

## 二、安装与接入模型

### 2.1 安装 ZCode

ZCode 提供 macOS / Windows / Linux 客户端。访问官网下载对应平台的安装包：

> 官网：https://zcode.z.ai

安装后首次启动会进入欢迎页，引导你完成模型接入。

### 2.2 三种接入模型的方式

ZCode 支持三种接入模型服务的途径，按需选择：

**方式一：连接 BigModel（智谱开放平台）**

智谱开放平台账号直连。支持 **GLM Coding Plan** 编程套餐、模型资源包与充值余额。适合国内开发者，延迟低、计费灵活。

配置入口：模型设置面板 → 选择 **BigModel** 供应商 → 完成账号连接 → 开启启用开关。

**方式二：连接 Z.ai**

Z.ai 账号直连，绑定后直接使用账号内的套餐与额度。

**方式三：第三方供应商**

接入任何兼容 **Anthropic / OpenAI 协议**的模型服务，包括团队自建通道。适合企业内部已有模型网关的场景。

### 2.3 选择 GLM-5.2

完成账号连接后，在模型设置中选择 **GLM-5.2**。ZCode 3.0 针对 GLM-5.2 系列做了深度适配，在以下方面表现稳定：

- 复杂项目理解
- 长任务规划
- 多轮上下文保持
- 连续代码修改

> ⚠️ 接入第三方协议的模型时，长任务的稳定性取决于该模型本身的能力。建议长程任务优先用 GLM-5.2。

## 三、用 ZCode Agent 发起任务

ZCode Agent 是 ZCode 自研的默认智能体，也是新建任务时最直接的提问入口。你可以在同一个工作台里：

- **提出需求**：用自然语言描述目标
- **补充上下文**：上传文档、贴入参考资料
- **引用文件**：让 Agent 精确读取项目里的具体文件
- **调用命令**：让 Agent 执行终端命令、看结果
- **选择模型与执行模式**：按任务特点切换

### 3.1 第一个任务：三段式描述法

好的任务描述能让 Agent 少走弯路。推荐用**三段式**：

```text
【目标】我要给现有项目加一个独立的用户注册/登录模块，支持邮箱注册。

【约束】
- 技术栈：React + FastAPI + SQLite
- 不要破坏现有的 GitHub OAuth 登录
- 密码要加密存储，用 JWT 签发登录态

【验收】
- 注册、登录、退出三个接口可用
- 有基本的单元测试
- 前端有一个登录弹窗
```

把目标、约束、验收标准讲清楚，Agent 的规划会更贴合你的预期，减少来回返工。

### 3.2 引用文件与上下文

当任务涉及现有代码时，显式引用关键文件，而不是让 Agent 全局搜索：

- 引用入口文件（如 `App.jsx`、`main.py`）让它理解结构
- 引用要修改的文件，给出明确改动范围
- 引用约定文件（如 `AGENTS.md`、设计规范），让它遵循你的编码标准

> 💡 这正是本项目（Learn-LLM）维护 `AGENTS.md` 的原因——把项目的人设、技术栈、编码标准写进去，Agent 每次都带着这些约束工作。

## 四、执行模式与 Plan 驱动

面对长任务，ZCode Agent 不会一路狂奔，而是按执行模式分阶段推进。

### 4.1 Plan（规划）先行

收到一个复杂任务后，Agent 会先产出**计划**：把大目标拆成有序的步骤，每步说明做什么、改哪些文件、预期产出。你要做的是**审查这份计划**：

- 步骤顺序合理吗？有没有依赖被忽略？
- 哪些步骤风险高，需要我盯着？
- 有没有过度设计？

确认计划后，Agent 才开始逐步执行。

### 4.2 边执行边验证

每完成一个步骤，Agent 会：

1. 做改动（编辑文件、跑命令）
2. **验证结果**（跑测试、看终端输出、检查文件）
3. 根据验证结果决定：通过则进入下一步，失败则自行修正或暂停问你

这个"执行 → 验证 → 收口"的闭环，就是长任务稳定性的来源。它不会在错误的中间状态上继续堆砌，每一步都是踏实落地的。

### 4.3 关键节点的人为确认

对于不可逆或外向型的操作（比如提交代码、推送远程、删除文件），Agent 会暂停等待你的确认。这保证了自动化与可控性的平衡：

- **可逆的本地改动** → Agent 自主完成
- **不可逆 / 外向操作** → 暂停确认

> 🔒 经验法则：把"需要我拍板"的节点写进任务描述里（"每完成一个模块先暂停让我 review"），主动管理确认节奏。

## 五、从规划到收口：一个完整流程

把前面的要素串起来，一个典型的长任务流程是：

```text
1. 描述任务（目标 / 约束 / 验收）
2. 引用相关文件与上下文
3. Agent 产出计划 → 你审查并确认
4. Agent 逐步执行：
     ├─ 改动代码
     ├─ 跑测试 / 看结果
     └─ 通过则继续，失败则修正
5. 关键节点暂停 → 你确认
6. 全部完成 → 最终验证 → 收口
```

### 小练习

试着让 ZCode Agent 完成一个跨多文件的任务，例如：

> "给本项目（Learn-LLM）的工具向导再加一个 ZCode 板块：在 tools-index.json 增加条目，写一篇 harness 教程，更新相关索引。完成后跑一遍前端构建确认没问题。"

观察它如何拆分步骤、引用文件、执行验证——这正是 ZCode 区别于短任务助手的地方。

## 小结

- **ZCode** 是面向 Long Horizon Task 的 ADE，核心是**长任务**和**稳定性**。
- 接入模型首选 **GLM-5.2**（深度联调），也支持 BigModel / Z.ai / 第三方协议。
- 用 **ZCode Agent** + 三段式描述法发起任务，主动引用文件和约束。
- **Plan 先行 + 边执行边验证 + 关键节点确认**，是长任务可控推进的关键。
- 与 CLI 助手、AI IDE 是互补关系，按任务特点选择。
