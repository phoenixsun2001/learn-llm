## 学习目标

完成本章后，你将能够：

- 用 `/goal` 为会话设定可校验的目标，让 Agent 自动迭代到完成
- 理解目标校验机制，知道什么时候该用目标模式、什么时候该用普通对话
- 用分组、工作区、时间线三种视图高效管理大量任务
- 借助工作区文件树浏览文件、查看 Git 状态并引用进对话

## 目标模式（Goal）

面对需要长时间运行的复杂任务，逐条指令地指挥 Agent 会非常疲惫。ZCode 提供了**目标模式**：用 `/goal` 为当前会话设定一个明确目标，设定后，ZCode Agent 会围绕目标**持续迭代**——每轮迭代结束自动进行目标校验，未完成则继续推进，确认完成才停下。

### 目标模式 vs 普通对话

| 维度 | 普通对话 | 目标模式（/goal） |
|------|---------|------------------|
| 交互方式 | 你发一条，Agent 做一步 | 你定目标，Agent 自主推进 |
| 适合任务 | 小改动、明确请求 | 复杂任务、需要多轮验证 |
| 你的角色 | 调度员，步步指挥 | 验收者，等待完成通知 |

### 如何设定目标

在对话中使用 `/goal` 命令，描述一个**可校验**的完成标准：

```text
/goal 让 src/auth/ 下所有导出函数都有 JSDoc 注释，
且 npm run typecheck 通过、npm run test 全部绿色
```

设定目标后，Agent 开始自主迭代。一个好的目标应当具备两个特征：

1. **可校验**：有明确的客观判断标准（测试通过、类型检查通过、lint 无报错）
2. **可分解**：Agent 能把它拆成可执行的子步骤

### 目标校验机制

这是目标模式的核心。每完成一轮迭代，Agent 会**自我校验**目标是否达成：

```text
迭代 1：扫描 src/auth/，识别缺少注释的函数 → 补充注释 → 运行 typecheck
校验：typecheck 通过？测试通过？注释覆盖完整？
  ├─ 全部满足 → 标记完成，通知你验收
  └─ 有未满足项 → 进入下一轮迭代，针对问题继续修复
迭代 2：修复 typecheck 报错 → 重新校验
...
```

这种「行动 → 校验 → 行动」的闭环，让 Agent 不会在「差不多」时就停下，而是真正把目标做到位。你不必盯着看，完成时它会通知你。

### 目标模式的最佳实践

- **给可执行的校验标准**：「代码更优雅」不可校验；「eslint 无 warning、测试覆盖率 ≥ 80%」可校验
- **范围要合理**：一次设定一个聚焦的目标，比设定一个庞大模糊的目标效果好得多
- **配合上下文引用**：用文件引用把目标限定在明确范围内，避免 Agent 漫无目的地改动

## 任务管理：三种视图

随着任务越积越多，左侧边栏提供了几个高频管理能力，帮助你组织任务列表。

### 分组视图

按自定义分组组织任务，适合把任务归类到不同的功能模块或项目阶段：

```text
分组：用户中心改造
  ├─ 任务：重构用户资料接口
  ├─ 任务：补充鉴权单元测试
  └─ 任务：迁移旧版用户表

分组：性能优化
  ├─ 任务：首屏加载优化
  └─ 任务：接口批量合并
```

你可以为分组设置颜色或命名，快速识别任务所属范畴。

### 工作区视图

按**工作区（Workspace）**组织任务。工作区通常对应一个代码仓库或项目根目录。如果你同时在多个仓库工作，工作区视图能让你清晰区分「这个任务属于哪个项目」，避免上下文串台。

### 时间线视图

按时间顺序排列任务，适合回顾工作进展、追踪最近的活动。当你需要「昨天那个任务做到哪了」「最近一周做了哪些事」时，时间线视图最直观。

## 工作区文件树

每个任务都关联一个工作区，左侧的**文件树**让你不离开 ZCode 就能完成文件相关操作。

### 浏览文件

文件树展示了工作区的目录结构，点击文件即可预览内容。这是引用上下文最快捷的方式——找到文件、点击引用，文件就进入了当前对话。

### 查看 Git 状态

文件树会标注每个文件的 Git 状态，让你一眼看清 Agent 改了哪些文件：

| 标识 | 含义 |
|------|------|
| `M` | 已修改（Modified） |
| `A` | 新增（Added） |
| `D` | 删除（Deleted） |
| `U` | 未跟踪（Untracked） |

这让 Agent 的工作成果一目了然，方便你决定哪些改动要保留、哪些要回退。

### 引用进对话

在文件树上选中文件后，可以一键把它引用进当前对话。结合目标模式使用，效果尤其好：

```text
（引用 src/api/payment.ts）
/goal 把这个文件里所有用 any 的地方替换成具体类型，
保证 npm run build 成功
```

## 一个完整的实战场景

把目标模式和任务管理结合起来，看看如何处理一个真实需求。

### 场景：为一个模块补充测试并修复类型问题

1. **创建分组**：在工作区新建分组「支付模块加固」
2. **新建任务**：在该分组下新建任务，描述需求
3. **设定目标**：

   ```text
   /goal 为 src/payment/ 下所有函数补充单元测试，覆盖率 ≥ 85%，
   同时修复 tsc 报告的所有类型错误，确保 npm run test 和 npm run build 都通过
   ```

4. **观察迭代**：Agent 自主迭代——写测试、跑测试、修类型、再跑——直到目标达成
5. **验收**：在文件树查看 Git 改动，确认测试和修复符合预期
6. **归档**：任务完成后归档，时间线视图里可随时回溯

整个过程，你的干预被压缩到最小：定目标、看结果。

## 小结

目标模式让 Agent 从「执行一步」升级为「完成一个目标」，而三种任务视图和工作区文件树则帮你高效地组织和追踪工作。两者结合，ZCode 才真正成为长程任务的得力伙伴。
