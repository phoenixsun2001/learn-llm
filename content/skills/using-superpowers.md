# Using Superpowers

这是整个 Superpowers 框架的**入口与总开关**。它的唯一职责是：在开始任何任务前，强制 Agent 先判断"是否有相关 Skill 可用"，而不是凭直觉直接动手。

## 核心规则：1% 原则

> 只要有 **1% 的可能**某个 Skill 适用于当前任务，就必须先调用它查看，而不是绕过。

这条规则针对的是 AI 最常见的失败模式：**理性化跳过流程**。Agent 会对自己说"这很简单，不需要流程"、"我记得怎么做"、"先探索一下再说"——结果偏离最佳实践。1% 原则把门槛设得极低，正是为了堵住这些借口。

## 什么时候触发

任务一开始就触发，包括：
- 收到一个新需求（"帮我实现 X"）
- 修一个 bug
- 重构一段代码
- 回答一个技术问题（是的，回答问题也是任务）

## 红旗信号：这些想法出现时，立刻停下

| 你心里的话 | 真实含义 |
|-----------|---------|
| "这很简单，不用流程" | 任务都会变复杂，先查 Skill |
| "我记得这个 Skill" | Skill 会演进，读当前版本 |
| "让我先探索一下代码" | Skill 告诉你**怎么**探索，先查 |
| "这不算一个任务" | 有动作就是任务，先查 |

## 如何应用

1. **收到任务** → 不要立刻动手。
2. **扫描可用 Skill 列表**，对照任务性质（计划？执行？调试？收尾？）。
3. **匹配到的 Skill 全部调用**（哪怕只是"可能"）。
4. **按 Skill 指引执行**，而不是按记忆执行。
5. 过程技能（brainstorming、debugging）**优先于**实现技能——它们决定**怎么做**，而不是做什么。

## 与其他 Skill 的关系

Using Superpowers 不解决具体问题，它是**调度器**：决定接下来调用哪个 Skill。它和 brainstorming（需求澄清）、test-driven-development（执行）、systematic-debugging（调试）、verification-before-completion（收尾）构成完整闭环。

记住一句话：**先查 Skill，再动手**。这是所有工程纪律的起点。
